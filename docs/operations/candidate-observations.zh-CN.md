# 无需模型的候选研究观察

[English](candidate-observations.md) · [冻结候选周期](research-candidates.zh-CN.md)

临时持仓、申报策略和实验信号属于不同证据。按实际收到的时间保存持有人的解释，不能把事后回忆写成当时的证明，也不能假设申报中的 Ranker 已存在。一页决策稿应区分真实意图、券商观察、模型未知项和面向未来的提案。

规则解释采用[2026-10-13正式规则第4.2条](https://fundconnecthk.com/docs/quant-competition-rules-2026-10-13.pdf#page=8)及[比赛复核说明](competition-review.zh-CN.md)。相关条件涉及累计空仓和全期指标；未达标影响答辩/奖项候选，并非连续十天就自动退赛。占位持仓既不证明策略有效，也不能认证达标。规则澄清本身不构成改仓或凑交易的指令。

## 保存研究检查点

原申报模型日记有意要求 PIT/模型/评分链，不能为了记录 ETF 假设而降低门槛或虚构 Ranker。下面独立、手动、离线的命令只使用冻结研究提案和行情回执，不导入模型、不生成权重、不授权订单：

```bash
python -m competition_tools.competition_review.candidate_observation \
  --proposal /external/sealed-proposal --session-date 2026-11-09 \
  --price-file /external/sealed-source/core.json \
  --output /external/new-observation
```

`--price-file` 可省略；CLI 不提供回填历史时间或联网采集选项。每次使用新的仓库外目录。提案封存、schema 和重算日历必须一致，交易日须为初始日或列出的检查点；当前 UTC 决定状态：

| 条件 | 状态 | 信号 |
| --- | --- | --- |
| 尚未到计划收盘 | `not_due` | 空 |
| 已过收盘后30分钟截止 | `missed_deadline` | 空 |
| 窗口内没有价格证据 | `blocked_missing_input` | 空 |
| 窗口内价格证据不通过 | `blocked_invalid_input` | 空 |
| 窗口内诊断输入有效 | `recorded_diagnostic` | 仅比较报表收盘与200个观察值均线 |

空信号不表示持有、卖出或空仓。不移动日期，迟到数据不能重建事前记录。保留全部版本，同一检查点只计一次，不能事后挑有利的一次。本机封存和时钟不构成独立的预登记认证。

有效诊断要求原始行情目录已封存且含 receipt.json。唯一成功回执须绑定核心标的/美元、真实字节和请求区间。采集须在计划收盘后开始、记录前完成，记录不能晚于固定截止；需该日及之前恰好200个完整 XNYS 交易日，以及正确的日线开盘事件时间。输出保存价格/回执哈希、采集时间、排除项和计算。缺失、不完整、未来、冲突、陈旧来源保持阻断；提案篡改或未知日期在生成输出前报错。

收盘/SMA 证据不认证历史拆股口径、供应方发布权、实际策略、模型验收、完整汇率/记账输入或交易就绪。[申报模型复核](competition-review.zh-CN.md)和[真实账本证据门槛](etf-rehearsal.zh-CN.md)保持不变。本流程不安装定时任务、不发消息、不操作账户。实际检查点前须采集真正完成的行情并复核数据口径；未来日历不等于已完成观察。

## 一页决策稿

私下记录：实际运行状态和归属说明；带日期的市值持仓与成交事实；与申报的差异；拟议研究候选的基准和规则；仍未批准的实际风险预算与责任人；输入缺失或不一致时的暂停/阻断条件；下一固定时间和所需回执。原解释与后续规则纠正分别保留，不悄悄修改申报或历史决定，也不把实验50%权重自动变成账户政策。
