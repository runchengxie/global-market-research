## Approaches
A large neural or Java rewrite adds uncertainty before the data question is answered. Reusing daily inputs as hourly bars gives incorrect coverage. Chosen approach: a bounded, independently packaged BTC/ETH spot study built on verified hourly archives, simple fixed baselines, explicit sentiment availability assumptions, and immutable observation receipts. Existing root owns acquisition/receipts; crypto leaf owns offline signals/accounting/fit; public site consumes aggregate JSON only. No imports between root and independent leaf.

Targets use a full-bar execution delay: features completed at t, entry at open t+step, exit at open t+2step. Purge fit rows whose exits reach the first test decision.

## Prospective receipts and monitoring
A new explicit protocol freezes the clock, candidates, dataset/source hashes, known cutoff, stop/budget rules and initial state. Freeze the exact final-fold price-only1h/4h Ridge coefficient/scaler contracts. Publicly call historical inputs AIVIX factor augmentation until indicator definitions are independently verified. Keep separate observed_bars, committed_forecasts and scored_forecasts counts. A forecast binds checkpoint/feature hashes, cutoff, generation UTC, modeled future entry/exit and prediction; generation must precede entry. Warmup features may support a forecast of a future period but do not count as new prospective bars. Score only after actual outcome bars arrive in a later immutable capture; stale daily factor forecasting stays blocked. First capture may record newly retrieved hourly prices as warmup and the old factor snapshot as stale; it is not future performance. Only bars ending after freeze and observed before later outcomes can count prospectively. Record period end, actual first receipt, retrieval and revision hashes separately. Never backdate, overwrite a receipt, import cached tails as future, or present future scores before outcomes exist. Provide a bounded credential-free manual capture CLI and a stable external installed runtime; do not activate shared services/schedulers or brokers.
A local monitoring report reads explicit owned acquisition/study/observation paths, verifies receipts/hashes and shows coverage, freshness as-of UTC, completed/failed/partial work, HTTP/fit budgets and blocking reasons. It performs no network I/O, state promotion or outbound messages. Unknown/missing evidence stays visible. Export public operational aggregates without private paths or response payloads.
