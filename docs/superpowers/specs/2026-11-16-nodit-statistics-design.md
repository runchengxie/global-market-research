# Bounded Nodit statistics acquisition

The competition-granted Nodit key has passed a small manual access probe. The owner does not know its quota and asks us to proceed with it. Implement a manual stdlib-only collector for the two verified Ethereum mainnet daily statistics: active accounts and transaction counts. This is the implementer's conservative choice under delegated execution, not a claim about the grant's scope.

Keep acquisition separate from broker execution and research promotion. A run accepts explicit ISO start/end dates (inclusive, at most 100 days, completed UTC days with the documented 00:30 publication delay), an external private credential file, a new external output directory and budgets. Default and maximum budgets are four attempts, 600 estimated CU, 1 MiB per response, and a cooperative 120-second time budget checked around network operations. This is not a hard process deadline: DNS/TLS/header receipt and internal chunk parsing can exceed it despite socket inactivity timeouts. Once control returns after expiry, block publication and further requests. Each statistics call reserves 150 estimated CU before I/O; use at least two seconds between requests. No retries, resume, scheduling, payment changes, wallet signing, arbitrary endpoints or additional chains. Stop on HTTP errors including 401/403/429; network errors retain uncertain-spend evidence. The local budget is per invocation and cannot enforce a provider/account-wide quota.

Read only NODIT_API_KEY from the given dotenv file without executing it. Reject missing, blank, duplicate, malformed and non-private POSIX credentials. Use HTTPS X-API-KEY headers to fixed official paths, refuse redirects and compressed/non-JSON responses, cap reads and suppress untrusted errors. Reject literal or JSON-escaped secret echoes before retaining a response. Enforce owner-private output files on POSIX; reject symlinks and source-repository destinations using the existing external path guard.

Freeze a credential-free plan before requests. Record each attempt and estimated CU before network I/O, retaining a receipt on failure. Save successful raw JSON bytes even when coverage is incomplete. Validate unique exact expected dates and nonnegative integer counts, reject duplicate JSON keys and nonfinite values, and normalize both metrics into one CSV only after both responses validate. Preserve source observation times; do not invent historical publication timestamps. A manifest inventories all plan/receipt/raw/CSV files by SHA-256 and size. A manual offline verify command rechecks exact inventory, schema, receipt/plan consistency and raw-to-CSV normalization. Hashes detect later edits relative to the retained manifest, not authenticity.

Alternatives considered: the official CLI adds dependencies and exposes a much wider API surface; a generic RPC adapter adds unrelated capabilities. A narrow two-endpoint collector fits the verified research need and limits unknown-quota consumption. Do not purchase or probe limits. Do not turn these metrics into an investment signal, substitute them for equity PIT fundamentals, or publish private datasets. Retain bilingual setup/limitations documentation. No runtime dependencies or execution contracts change.

Acceptance: offline tests exercise valid acquisition/verification, budget preflight and charged failures, error redaction, output exclusivity, credential/path rejection and corrupted/partial data. Root CI checks pass. One bounded real 90-day run uses two requests (300 documented CU), with private provenance and retention inventory, followed by offline verification. An independent code review and passing current-head CI precede standing-authorized integration.
