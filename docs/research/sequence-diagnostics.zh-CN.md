# 已训练序列模型的诊断

[English](sequence-diagnostics.md)

通过本地诊断浏览器，可以检查已保存模型为什么很少交易，以及控制敞口和风险后比较结论是否改变。这是对已经看过的历史数据做回顾分析，不会形成独立测试、重新训练模型、证明交易有效性或授权执行。

## 生成本地报告

在独立的 equity 包中安装锁定的 `predictive` 和 `neural` 依赖，传入原始封存实验和准确的数据清单摘要：

```bash
python -m equity_lab.study.sequence.cli diagnose \
  --manifest "$DATA_ROOT/global-market-research/datasets/<snapshot>/manifest.json" \
  --expected-sha256 '<manifest-sha256>' \
  --run "$DATA_ROOT/global-market-research/research/lstm-moe/runs/<sealed-run>" \
  --output "$DATA_ROOT/global-market-research/research/lstm-moe/<new-diagnostic-directory>"
```

输出必须是源码目录之外的新目录，并与输入分开。诊断使用已保存的检查点、缩放器和特征顺序重建验证段、测试段概率；测试概率绝对误差不得超过 `1e-6`，二元仓位账本误差不得超过 `1e-10`。结束前再次校验数据字节与最初绑定的父实验校验清单。

处理预算为 30 分钟，超时会明确标为未完成。在诊断处理阶段收到 SIGTERM 或键盘中断，会保留已完成记录；初始化失败时可能尚未创建结果目录。当前中断案例可能留下账户文件，但只有汇总中的记录算完成。时间检查发生在操作之间，单次操作可能晚于截止时间结束，但之后不能把整轮标为完成。

直接打开 `browser.html`。数据、脚本、中英文文案、SVG 曲线和数值表都在文件内，不访问网络，不启动服务器，禁用 JavaScript 时仍有基本表格。可按模型、折、种子、费用和对照筛选，也可打开另一份诊断 `summary.json`（最多 50 MiB）。真实报告保留在本地；公开 Pages 继续只展示合成示例。

## 怎样理解结果

每个案例包含类别比例、概率分位数、Brier 分数、对数损失、可定义时的 AUC、可靠性分箱、校准误差，以及相对拟合段类别先验的 Brier 改善。概率全部低于 0.5 能解释空仓，但单凭这一点不能区分合理先验与无效预测。路由摘要区分学到的门控与固定等权。

参数量接近的单 LSTM、等权专家、稠密 MoE、稀疏 MoE 都与原账户进行六组对照：固定 25%/50% 仓位、验证段冻结敞口、验证段冻结波动率比例、因果 10% 波动率控制、验证段选择阈值。所有方案使用相同日期与 0/5/20/40 基点费用，支持只做多的分数仓位，计入首次开仓和最后平仓。账本使用调整价格单位，不包含股息、融资或杠杆。

五个阈值为 0.35、0.425、0.5、0.575、0.65，仅按验证段扣除 5 基点费用后的日均收益选择；并列时先靠近 0.5，再选更大的阈值。原训练早停也使用过验证段，因此这是额外的回顾选择，并非独立确认。本轮不拟合概率校准器。

风险目标只来自验证段，不使用未来测试风险。因果波动率对照只读取每次特征截止时已经知道的 20 个组合收盘收益。报告分别展示目标仓位差、实际平均开盘敞口差，以及各费用下相对原模型的实际年化波动率差。这些对照不保证测试段风险完全相等。采用模型或阈值前，还需要按相同日期配对比较并检查不确定性。

## 数据证据与未来验证

根目录命令复用数据所有者已有的字节和证据审计：

```bash
python -m competition_tools.evaluation.sequence_governance \
  --manifest '<manifest>' --expected-sha256 '<sha256>' \
  --start YYYY-MM-DD --end YYYY-MM-DD --output '<new-external-directory>'
```

证据清单保留六项阻塞：时点股票池、历史证券身份、公司行动覆盖、历史可得时间、所有者来源证明（含使用和公开展示权利）、留出评估治理。未来协议仍是需要所有者审阅和独立证据的草案，研究接受与执行授权始终为假。命令不预留测试，也不安排数据采集。草案固定候选范围、日期、费用、选择规则和停止条件，不把已经检查过的日期重新称为未知数据。

## 工程维护证据

Code size 工作流下载并校验 cloc 2.10 的 SHA，按模块报告提交中的代码总量和 PR 增量，区分实现、测试与其他文本。统计包含重复代码，不包含锁文件、依赖和构建产物；只作参考，不设行数配额。本地使用 `competition_tools.code_size --help` 查看同一接口。`competition_tools.source_inventory` 列出字节相同的文件、导入与入口；静态调用者缺失不能证明代码无用。导入边界检查限制模型依赖回放或交易模块。CI 输出最慢的 15 项测试，便于后续有针对性地优化。

模型和账本假设见[序列研究说明](lstm-moe.zh-CN.md)。
